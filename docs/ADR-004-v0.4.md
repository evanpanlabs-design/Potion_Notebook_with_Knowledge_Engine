## 1. 范围与动机

v0.3 交付的是「自主性 + 异步交互」：AI 会自己排程、自己体检、和人异步对话，但能力半径锁死在四个内置只读工具 + 既有管线。v0.4 回答的问题是：**如何在不破坏围栏的前提下让 agent 能干的事变多、变可信**。

三条主线对应三种扩张方向：

- **接入外部世界**（MCP）：agent 能查的东西从「本库 + Tavily」扩到任意 MCP server 暴露的只读资源
- **加载用户方法论**（Skill）：D13 的启动级注入升级为完整渐进披露，用户可用 skill-creator 造 skill 直接丢进 `skills/` 生效
- **打开写路径**（受闸门写操作）：agent 从「只能建议」升级为「能起草变更」，但落盘仍走人工审核——这是 ADR-002 阶段 C「可信度」叙事的核心一步

**明确不做**（维持 ADR-003 决策）：代码执行与 tool 生产（v0.5+）、用户记忆系统（未想清楚）、图谱社区化（挂条件：节点 > 300）。

## 2. v0.4 方案要点

### 2.1 F-1 MCP 接入（D2/D3）

复用调研结论（ADR-003 §2）：pi-mcp 是独立客户端，stdio / Streamable HTTP / 内存 transport 全齐，零 pi 依赖，测试可用内存 transport 零网络覆盖。

落地形态：

- `data/mcp-config.json`：注册表（name / transport / command|url / enabled），设置页可视化管理（与 Tavily/MinerU 配置同层同风格）
- agent 构建工具表时：内置四件套 + web_search + 各 enabled MCP server 的工具（启动时拉取工具清单并缓存）
- **围栏分级**：
  - 一期：MCP 工具按声明过滤——名称/描述含 read/list/search/get 类语义的进白名单，含 write/create/delete/update/push 类的**不进工具表**（模型根本看不到）
  - 二期（依赖 F-3 落地）：写类工具可见但产出变更提案，走 review queue
- 工具描述注入 token 预算：单 server 工具数上限（建议 20）+ 描述截断，防 MCP 大清单撑爆上下文
- 失败语义：server 启动失败 / 调用超时 → 工具执行返回 isError 结果（模型自行换路），不影响 loop 存活

### 2.2 F-2 Skill 渐进披露补全（D4）

D13 已做：`skills/<dir>/SKILL.md` frontmatter（name/description）启动级注入 system prompt。v0.4 补全：

- 新增只读工具 `read_skill`：参数 `name`，返回该 skill 的 SKILL.md 全文（渐进披露第二级）
- system prompt 注入文案改为「可用技能列表 + 需要时用 read_skill 读取完整方法」——模型自行判定相关性，命中才加载，不预载全文
- 预算护栏：单次任务 read_skill 调用上限（如 3 次）；SKILL.md 全文超长截断（如 16k 字符）
- 与 CatPaw skill-creator 产物互通验证：拿 1-2 个真实 skill 放进 `skills/` 做验收标准

### 2.3 F-3 受闸门写操作（D5）

当前 agent 工具全只读，workbench「执行链路」节是占位说明。v0.4 开第一批写工具，但**写通道不开洞**：

- `apply_edit` 工具：agent 提交结构化变更提案（target page / 完整新正文 / 理由 / 引用依据）
- server 侧处理：**不落盘**，产出 `proposals/` 变更草案（或直接进 review queue 的待审条目），workbench 执行链路节记录提案状态
- 人工在审核页处置：通过 → 走既有 gate executor 落盘；驳回/返修 → 意见回流给 agent（下次任务上下文可见）
- 限制：单任务提案数上限（防刷屏）；提案目标仅限 `wiki/`（notes/ 永远只由人写，红线不动）

这条是 v0.4 最值得作品集讲的一笔：「agent 从建议者变成起草者，但落盘权始终在人和闸门」。

### 2.4 F-4 workbench 图谱化入口（D6）

- 总览/工作台页加「消化为项目经验」按钮（单条任务，人工触发）：把该任务四节轨迹作为素材走 ingestSource
- 产出的经验页进 review queue 正常审核，类型建议 `experience`
- 不做自动消化（agent 任务量大，自动 ingest 会污染库；人工挑有代表性的消化）

### 2.5 F-5 audit 深化（D7，观察项）

v0.3 audit 初筛是启发式（Jaccard/度数/token 重叠）+ 单轮 LLM 判定。v0.4 候选改造：audit 管线复用 runAgentLoop，让模型用 search_kb/read_page 工具自己核实嫌疑（如读疑似重复的两页全文再判 merge）。

**触发条件**：v0.3 实测中 audit 建议的采纳率低（误报多）才做；若启发式初筛+单轮判定已够准，此模块降级不做，省下的预算给 F-1/F-3。

## 3. v0.5 展望（占位，v0.4 收口时立 ADR）

- **代码执行**：pi-codemode QuickJS(WASM) 沙箱跑模型写的 JS——嵌套工具调用不进 LLM 上下文、只回脚本输出（成本与上下文双友好）。用户场景：批量数据变换、本地计算、复杂检索编排
- **tool/skill 生产与图谱化**（ADR-003 设想 #7）：用户教 AI 造工具，工具本身作为知识页进库被引用；依赖 v0.4 的工具注册表与写闸门稳定
- **社区化**：节点数持续 > 300 时启动 Louvain 聚类（原架构已留规划）

## 6. 优先级重排规则（v0.3 实测驱动）

草案接受前，先跑 1-2 周真实使用，按 dominant pain point 重排：

| 实测主导痛点 | v0.4 优先级调整 |
|---|---|
| 「AI 能干的事太少」（检索不到外部信息/没有方法论） | F-1 MCP + F-2 Skill 提前，F-3 写操作推后 |
| 「AI 干的事不可信」（audit 误报/建议质量差） | F-3 写闸门 + F-5 audit 深化提前，MCP 推后 |
| 「异步任务噪音大」（日报/通知贴太多太碎） | 新增小模块：通知聚合与静默策略（本文未展开，实测后补） |
| 无明显痛点 | 按本文默认顺序执行 |

## 7. 风险与守门

- **MCP 供应链风险**：第三方 server 可能恶意/不稳定——工具描述进上下文前清洗；写类工具一期根本不进白名单；server 崩溃不影响 loop（isError 降级）
- **上下文预算**：MCP 工具清单 + skill 列表 + read_skill 全文都可能膨胀——各级都有上限护栏，且 compaction（D13 已接入）作为最后防线
- **写闸门绕过风险**：apply_edit 只产出提案不落盘；notes/ 只由人写的红线写进工具 schema 描述与 server 校验双重防线
- **scope 蔓延**：F-5 明确挂条件；§6 重排规则避免「全都想要」——v0.4 只保证 F-1~F-4 四件落地

## 8. 与 ADR-002 三阶段的对账

- 阶段 A（工具化检索）：✅ v0.3 完成
- 阶段 B（自主性与异步交互）：✅ v0.3 完成（定时任务/收件箱/便利贴/workbench）
- 阶段 C（能力可信扩张）：v0.4 落 MCP/Skill/写闸门三件，v0.5 落代码执行/工具生产——「可信」的判定标准始终是：每次扩张都带着对应的围栏一起交付

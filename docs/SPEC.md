## 1. 术语与对象模型

| 对象 | 定义 | 谁拥有 | 可变性 |
|---|---|---|---|
| **Source** | 原料层：PDF / 网页 URL / Markdown，导入后不可变 | 系统 | 不可变（重新导入 = 新来源） |
| **Wiki** | 理解层：实体页 / 概念页 / 来源摘要页 / 综述页 | Agent 维护，人审批 | Agent 可提案修改，覆盖必经人审 |
| **Note** | 思考层：人的笔记，自由写作 | 人 | 只有人能改；Agent 只有建议权 |
| **Thread** | 对话层：一次提问/讨论及其引用 | 系统 | 可归档为 Note 或 Wiki 页 |
| **Graph** | 显化层：以上四层关系的投影与洞察 | 系统 | 只读投影，随库自动更新 |
| **Schema** | AGENTS.md：Agent 的操作规程 | 人与 Agent 共同演化 | git 可追溯 |

**权限矩阵（信任设计的根）**

| 操作 | Agent | 人 | 约束 |
|---|---|---|---|
| 写 Source | ❌ | ✅ | 导入后即冻结 |
| 写 Wiki | 🟡 提案 | ✅ 审批后生效 | 覆盖性修改必进 Review Queue |
| 写 Note | ❌（仅建议） | ✅ | 单次显式授权除外 |
| 写 Schema | 🟡 提案 | ✅ | 变更 git 可追溯 |
| 删除任何页 | ❌ | ✅ | 级联删除走 Review Queue |

## 2. 全局 UX

### 2.1 首次启动

无库状态显示两个入口：**新建知识库**（选空文件夹，30 秒内可用）/ **打开已有库**（选含 sources/notes/wiki 的文件夹）。两者都进入主界面。

### 2.2 全局布局

三栏 + 面板切换：左侧库树（sources/notes/wiki 三区分组）/ 中部内容区 / 右侧上下文面板（Chat、引用、diff）。顶部导航：**库 · 编辑 · Chat · Graph · Review · Lint**。面板尺寸可拖拽调整。

### 2.3 统一状态语言

所有异步操作（ingest、query、lint）共用同一套状态表达：**排队中 → 处理中（带阶段名）→ 完成（带结果摘要）/ 失败（带原因与重试按钮）**。任何时刻界面不出现无解释的空白或转圈超过 30 秒。

### 2.4 成本可见

每次 ingest/query 结束显示 token 消耗与估算费用；设置页有累计账单页。dogfooding 期每周可对账。

### 2.5 空态

每个面板都有可操作的空态：sources 空 → 引导拖入第一篇；wiki 空 → "投喂后 wiki 会自动成形"；Chat 空 → 示例问题；Graph 空 → 说明图谱随 wiki 增长；Review 空 → "当前无人审事项"（这是好状态，明示）。

## 3. 功能规格

### F1 · 本地文件库

**用户故事**：作为用户，我想打开一个文件夹作为知识库，30 秒内开始投喂，并且我的数据始终是纯 Markdown 文件。

**触发入口**：首次启动引导 / 顶栏库切换菜单。

**主流程**
1. 选择"新建知识库"，指定一个文件夹
2. 系统初始化目录：`sources/`、`notes/`、`wiki/`（含 `entities/ concepts/ sources/ queries/ synthesis/`）、`index.md`、`log.md`、`AGENTS.md`
3. 自动 `git init` 并完成首次提交（内容为目录骨架 + AGENTS.md 默认模板）
4. 进入主界面，sources 面板显示空态引导

**状态与空态**：新库 = 三区全空 + 投喂引导；打开已有库 = 启动时扫描全部 md，构建内存索引（frontmatter + wikilink），扫描进度在启动页显示。

**错误与边界**：所选文件夹非空且不含库标志 → 提示"把现有文件导入为 sources，或另选文件夹"，二选一，不自动猜；中文/带空格路径必须正常；无写权限 → 明确报错并建议换目录。

**验收标准**
- [ ] 新建库从点击到可用 ≤ 30 秒
- [ ] 库内全部内容为 Markdown + frontmatter 的本地文件，Obsidian 可直接打开同一文件夹
- [ ] `[[wikilink]]` 与 frontmatter 兼容 Obsidian 惯例
- [ ] 关闭应用重开，库状态完整恢复

### F2 · Source 摄入

**用户故事**：读到好东西，一键 clip 或拖入，然后继续干别的——知道系统会消化它。

**触发入口**：拖拽文件到左栏 sources 区 / "添加来源"按钮（三种方式：上传文件 · 粘贴 URL · 粘贴文本）/ F14 Web Clipper（M4）。

**主流程**
1. 拖入文件（或提交 URL/文本）
2. 原始文件存入 `sources/`（URL 抓取正文转 Markdown 落盘；文本直接存 md），计算 SHA256
3. SHA256 命中缓存 → 标记"已消化，跳过"，直接完成
4. 未命中 → 进入持久化 ingest 队列，Activity 状态条显示"排队中"
5. 处理中显示两阶段进度（见 F3）；完成后状态条变成"完成：生成 N 页，更新 M 页"

**状态与空态**：队列中/处理中/完成/失败四态；失败显示原因（解析失败 / LLM 超时 / 配额不足）与重试按钮；批量导入逐个串行处理，队列崩溃恢复后未完成任务自动续跑。

**错误与边界**：扫描版 PDF 解析失败 → 建议启用 MinerU 类管道或放弃该来源；URL 抓取失败（反爬/超时）→ 显示原因，允许"另存为手动粘贴文本"；同一文件重复拖入 → SHA256 判重，提示跳过；单篇超过 2 分钟 → 状态条持续显示阶段，不假装卡死。

**验收标准**
- [ ] 单篇摄入 ≤ 2 分钟（Markdown / PDF / URL 各至少一例）
- [ ] 每篇来源生成带 `sources[]` 溯源的摘要页
- [ ] 原始 source 文件导入后内容不可变（git 中无任何对 source 的内容修改提交）
- [ ] 未变化来源重复导入被缓存跳过，不产生重复页面
- [ ] 每次摄入的 token 消耗对用户可见

### F3 · 两段式 Ingest

**用户故事**：我想知道 Agent 到底读到了什么、改了什么——每一篇来源触达的页面更新都可追溯、可回滚。

**触发入口**：F2 队列自动触发；手动"重新消化"某来源。

**主流程**
1. **分析阶段**（状态条显示"分析中"）：LLM 读来源 + `index.md` + 相关页，产出结构化分析：关键实体/概念、与现有 wiki 的关联、与已有知识的矛盾、建议更新的页面
2. **生成阶段**（"生成中"）：LLM 依分析产出页面更新方案（新建/更新哪些实体页、概念页、来源摘要页），全部带 `sources[]`
3. 写入闸门校验（frontmatter schema + tag 词表），校验失败不落盘、任务标记失败可重试
4. 通过校验 → 更新 `wiki/` 相关页 + `index.md` + `log.md`，**一次 ingest = 一次 git 提交**
5. 矛盾/覆盖/合并建议写入 Review Queue（不阻塞流程）
6. Activity 完成态显示触达页面清单，点击任一页可看本次 diff

**状态与空态**：Activity 面板是 ingest 的家——显示每篇来源的两阶段进度、触达页面数、token 消耗；点击"查看 diff"直接看本次提交的 git diff。

**错误与边界**：结构化输出校验失败 → 自动重试 ≤ 3 次（重试换措辞提示），仍失败则任务失败，来源保留在队列可重试；LLM 中断 → 队列项保持"处理中"状态并在下次启动时重新执行（pi-durable 保障）；矛盾判定 → 一律进 Review Queue，绝不在 ingest 中静默覆盖。

**验收标准**
- [ ] 一篇来源触达的所有页面更新在单次 git 提交内，可 `git revert` 整体回滚
- [ ] 每个新建/更新页面 frontmatter 均含 `sources[]`
- [ ] `log.md` 追加形如 `## [YYYY-MM-DD HH:mm] ingest | <来源标题>` 的可 grep 条目
- [ ] `index.md` 在每次 ingest 后保持与实际页面一致
- [ ] 矛盾判定进 Review Queue 而非直接覆盖既有页面

### F4 · Note 编辑器

**用户故事**：笔记是我的领地。我要流畅地写，随手 `[[引用]]` wiki 页，但 Agent 永远不能擅自改动我的文字。

**触发入口**：左栏 notes/ 区"新建笔记" / 打开已有笔记；双击 wiki 页可查看（wiki 页编辑走 Review，不走此通道）。

**主流程**
1. 在 Milkdown 编辑器中写作，自动保存（防丢）+ 手动保存均触发 git 提交
2. 输入 `[[` 触发自动补全：候选 = 全部 wiki 页（含实体/概念/来源摘要）+ 全部笔记，支持中文标题、别名匹配
3. 选中候选生成 `[[页面标题]]`；若目标页不存在，保存为"悬链"，Lint 可扫描
4. 写作中可随时划选文字，右键菜单："向系统提问"（带选中文本入 Chat）/ "建议提升到 Wiki"（F9）
5. Agent 对笔记的建议以**侧栏批注**形式呈现，永不直接修改正文

**状态与空态**：编辑中 = 自动保存标识 + git 提交记录；未保存离开 → 确认提示；笔记列表按修改时间排序。

**错误与边界**：`[[` 目标不存在 → 允许保存为悬链（不强制先建页）；两个页面同名 → 补全列表显示路径区分；Agent 工具对 notes/ 的任何直接写入被闸门拒绝（这是 F4 的核心验收）。

**验收标准**
- [ ] Milkdown 编辑含 `[[wikilink]]`、frontmatter 的笔记正确保存与回读
- [ ] `[[` 补全同时列出 wiki 页与笔记，含别名匹配
- [ ] **git 历史可证明 notes/ 的每次内容变更都来自人的操作**（Agent 提案不直接落盘）
- [ ] 编辑器在 5000 字笔记内输入无明显卡顿

### F5 · Query

**用户故事**：我提问，答案带引用——每条断言都能跳回它依据的 wiki 页或原始来源。

**触发入口**：Chat 面板；笔记内划选文字"向系统提问"。

**主流程**
1. 用户提问 → 检索管道自动运行（界面上可展开"查了哪些页"的检索轨迹）
2. 答案流式输出，断言带 `[1][2]` 编号引用
3. 引用面板列出所用页面（分组：wiki 页 / source 页），点击跳转
4. 答案下方提供"存为笔记 / 存入 Wiki"（见 F6）
5. Thread 可保存、重命名、删除；好答案不随对话蒸发

**检索轨迹（可展开）**：显示本次走了级联的哪几段（词法命中 N 页 → PPR 扩展 M 页 → 预算内选取 K 页）。透明度本身就是差异化。

**状态与空态**：检索中 → 回答流式 → 完成；检索无结果 → 如实回答"库内无依据"，不编造；开关"只读原文模式"（仅从 sources 生成答案，不经过 wiki 综合）。

**错误与边界**：LLM 失败/超时 → 显示原因并允许重试；上下文超预算 → 自动收窄选页并在轨迹中注明；引用页在回答后被删除 → 引用面板标记"页面已删除（git 可查历史）"。

**验收标准**
- [ ] 答案中每条关键断言可跳转到对应 wiki 页 / source 页
- [ ] 库内无依据时明确回答"无依据"，不编造（用对抗性测试问题验证）
- [ ] 规模目标内（500 来源 / 2000 wiki 页）首 token < 2 秒
- [ ] Thread 保存后重开完整恢复

### F6 · 归档

**用户故事**：一次问答里挖出的好答案，不该死在聊天记录里。一键把它变成笔记或 wiki 页，引用自动跟过去。

**触发入口**：每条回答下方的"存为笔记 / 存入 Wiki"。

**主流程**
1. 点击归档 → 预览（frontmatter 已自动填好：类型、问题、`sources[]`、生成时间）
2. **存为笔记**：落入 `notes/`（此后完全归人所有，Agent 不可改）
3. **存入 Wiki**：落入 `wiki/queries/`，随后**再走一次 ingest** 抽取其中的实体/概念并入知识网络（llm_wiki 验证过的做法：比单纯存档值钱）
4. 两种方式均产生 git 提交，可在 Activity / git log 追溯

**错误与边界**：归档目标名与现有页冲突 → 提示改名或覆盖进 Review；引用列表为空 → 警告"无来源断言，建议确认"。

**验收标准**
- [ ] 归档内容自动带 `sources[]` frontmatter，不丢失引用
- [ ] 存入 `wiki/queries/` 的答案会触发实体/概念抽取，图谱中出现对应节点
- [ ] 存为笔记后该文件受 Note 神圣性保护

### F7 · Graph

**用户故事**：打开图谱，看见知识的形状——哪里密集、哪里是孤岛、谁和谁意外相连。

**触发入口**：顶栏 Graph 面板。

**主流程**
1. 打开即渲染：节点 = 全部 wiki 页 + notes（可按类型过滤），边 = `[[wikilink]]` + `sources[]` 共现
2. 边权 = 4 信号相关度（直链 ×3 / 来源共现 ×4 / Adamic-Adar ×1.5 / 类型亲和 ×1），决定边粗细与颜色深浅
3. 悬停：邻居保持高亮，其余淡出，边显示相关度分值
4. 点击节点打开对应页面；图与内容区联动
5. 着色切换：按页面类型 / 按 Louvain 社区；图例显示类型计数或社区凝聚度
6. 布局位置缓存：数据更新后不整图跳动

**状态与空态**：空态解释"图谱随 wiki 增长"；加载中显示节点计数进度。

**错误与边界**：超大规模（>500 节点）→ 自动只显示相关子图或提供过滤（按类型/社区/来源筛选），不降帧率；wikilink 解析异常 → 该边跳过并在 lint 报告。

**验收标准**
- [ ] 200 页规模下缩放、平移、悬停高亮流畅
- [ ] 悬停时邻居高亮、非邻居淡出，边显示相关度
- [ ] 类型/社区两种着色可切换，图例信息正确
- [ ] 点击节点跳转页面，图与内容联动

### F8 · Schema 文件

**用户故事**：我要能改变 Agent 的操作规程——改了 AGENTS.md，下一次消化的行为就跟着变，全程 git 可追溯。

**触发入口**：设置 → "操作规程（AGENTS.md）"。

**主流程**
1. 在 Milkdown 中直接编辑 AGENTS.md（页面类型定义、ingest 规则、命名/tag 约定、lint 规则）
2. 保存 → git 提交；语法/结构错误即时提示
3. 下一次 ingest 读取新版本生效；schema 变更历史在 git log 可查

**错误与边界**：schema 损坏（YAML/frontmatter 语法错误）→ 保存前拦截并定位错误行；Agent 也可提议 schema 修改，但作为 Review 项由人批准（见权限矩阵）。

**验收标准**
- [ ] 修改 AGENTS.md（例如增删一种页面类型）后，下一次 ingest 的产出结构肉眼可见变化
- [ ] schema 语法错误在保存前被拦截
- [ ] 每次修改有独立 git 提交

### F9 · Note → Wiki 提升流（P1 · M3）

**用户故事**：一段笔记想清楚了，一键"提升"——Agent 替我起草成 wiki 页，我看 diff 后批准。

**触发入口**：笔记内划选文字 → 右键"建议提升到 Wiki" / 笔记页菜单。

**主流程**
1. 选定笔记段落（或全文），发起提升
2. Agent 起草：结合该笔记引用的 sources 与相关 wiki 页，生成带 `sources[]` 的页面草稿（实体或概念页），存入 Review Queue
3. 人在 Review 中看**完整 diff**（新建页全文 / 对既有页的合并方案），三选一：批准入库 / 拒绝 / 让 Agent 重拟
4. 批准 → 落入 `wiki/`，git 提交；原笔记**保持原样不动**（提升是复制+结构化，不是搬移）

**错误与边界**：笔记无任何来源关联 → 草稿标注"未溯源内容"，人可放行（个人判断也是合法知识）但 lint 会持续提示；目标页已存在 → 走合并方案进 Review，不覆盖。

**验收标准**
- [ ] 提升产物为带 `sources[]` 的结构化 wiki 页，笔记原文一字不改
- [ ] 全流程经 Review Queue，无直接落盘路径
- [ ] 拒绝/重拟分支可用且状态正确

---

### F10 · Wiki → Note 拉取（P1 · M3）

**用户故事**：wiki 页写得太"成品"了，我想把它拉回思考层再加工——像把书页撕进草稿箱，但引用还在。

**触发入口**：wiki 页菜单 → "拉取为笔记草稿"。

**主流程**
1. 发起拉取 → Agent 生成笔记草稿：正文 + 保留全部 `sources[]` 与 `[[wikilink]]`
2. 草稿落入 `notes/`，**从此归人所有**，人自由改写，Agent 不再碰
3. git 提交一次（`note: pull from <wiki页>`）

**错误与边界**：同名笔记已存在 → 自动加后缀（`-草稿-2`）并提示；原 wiki 页不受任何影响（拉取是投影，不是剪切）。

**验收标准**
- [ ] 草稿保留原页全部来源引用与 wikilink
- [ ] 原 wiki 页内容与 frontmatter 无任何变化
- [ ] 拉取后的草稿受 Note 神圣性保护

---

### F11 · Review Queue 面板（P1 · M3）

**用户故事**：Agent 只有建议权。所有它想做的覆盖、合并、矛盾判定，都排好队等我说了算。

**触发入口**：顶栏 Review 面板（导航徽标显示未处理数）。

**主流程**
1. 队列列出待审项：**矛盾判定 / 合并建议 / 覆盖建议 / 提升草稿 / 来源级联删除**
2. 每项展示：说明、涉及的页面、**完整 diff**、预生成的动作按钮
3. 动作是**预定义枚举**（批准创建 / 批准合并 / Deep Research / 跳过），LLM 不能发明动作——防止幻觉操作
4. 批准 → 执行 → git 提交（`review: <id> <action>`）；跳过 → 保留记录但不执行
5. 处理历史在面板内可查，对应 git 提交可跳转

**状态与空态**：空态明示"当前无人审事项"（好状态）；未处理数徽标同步更新；ingest 进行中实时入队。

**错误与边界**：执行时目标页已被人工修改 → 冲突提示，diff 重新计算，不盲写；执行失败 → 队列项回到未处理，原因显示。

**验收标准**
- [ ] 覆盖性操作 100% 经 Review Queue，代码层不存在绕过路径（含测试用例）
- [ ] 每个动作按钮来自预定义枚举
- [ ] 每次决策产生独立 git 提交，可回滚
- [ ] `reviewed: true` 的页面不被 Agent 覆盖（只能追加建议）

### F12 · Lint 面板（P1 · M2 基础版）

**用户故事**：定期体检：矛盾、孤儿页、陈旧断言、知识缺口，一眼扫出，一键定位。

**触发入口**：顶栏 Lint 面板 → "扫描"；设置里可开周期提醒。

**主流程**
1. 扫描四类：**矛盾**（页面间断言冲突）/ **孤儿**（无入链页面）/ **陈旧**（新来源使旧断言过时）/ **缺口**（高频提及但无独立页面的概念）
2. 报告按类型分组显示计数，逐项可点击**定位到页面与行**
3. 每项可"生成修复建议"：Agent 产出带 diff 的提案 → 进 Review Queue 人审执行（Smart Fix 永不直接落盘）
4. 缺口项可"生成阅读建议"（下一步该找什么来源）

**状态与空态**：扫描中显示进度；空态显示"wiki 健康"与上次扫描时间。

**错误与边界**：扫描是只读操作，失败不影响库；修复建议数量大 → 分批入 Review，避免队列爆炸。

**验收标准**
- [ ] 四类问题各能用测试库稳定扫出（每类至少一例）
- [ ] 每项可一键定位到具体页面
- [ ] 一键修复以 Review 提案形式执行，永不静默写盘

### F13 · 图谱洞察（P1 · M4）

**用户故事**：图谱不只是好看——让它告诉我孤岛在哪、哪片社区连接太弱、哪个节点是桥，以及下一步该读什么。

**触发入口**：Graph 面板 → "洞察"侧栏。

**主流程**
1. 自动分析四类洞察：**孤岛页**（度 ≤ 1）/ **稀疏社区**（凝聚力 < 0.15 且 ≥ 3 页）/ **桥节点**（连接 ≥ 3 个社区）/ **意外连接**（跨社区/跨类型的高相关度边）
2. 洞察以卡片呈现：每张可点击 → 图中对应节点/边高亮，其余淡出
3. 孤岛/稀疏/桥卡片可"生成阅读建议"：Agent 结合 `index.md` 与库的主题方向，产出具体到检索词的下一步阅读建议，可存为 Note 或进 Review
4. 意外连接卡片可标记"已审视"，不再重复出现

**错误与边界**：图太小时（<20 节点）洞察降级为简单的孤岛列表，避免过度解读。

**验收标准**
- [ ] 四类洞察各能从构造的测试图稳定产出
- [ ] 点击洞察卡片，图中对应元素高亮定位
- [ ] 阅读建议可一键生成并带引用与检索词

### F14 · Web Clipper 浏览器扩展（P1 · 机动项）

**用户故事**：在浏览器里读到好文章，一键剪进知识库，正文自动转 Markdown，后台自动消化。

**触发入口**：浏览器扩展图标 / 快捷键（`Alt+Shift+L`）。

**主流程**
1. 点击扩展 → 用 Readability 类提取正文（去广告/导航/侧栏），转 Markdown
2. 发送到本地后端（127.0.0.1），存入 `sources/`，自动进入 ingest 队列
3. 剪藏成功即返回确认；应用未运行时扩展保留预览，待启动后重发

**错误与边界**：正文提取失败（SPA/付费墙）→ 提示改用"手动粘贴"；本地端口未开 → 明确提示先启动应用。

**验收标准**
- [ ] 剪藏 5 秒内出现在库 sources 区并进入队列
- [ ] 提取正文干净（无广告/导航残留），保留标题与链接
- [ ] 应用未运行时的离线暂存与重发可用

## 4. MVP 地狱测试（M2 收尾必过）

新用户（无任何背景）在 30 分钟内完成，全程录屏：

1. `npm install && npm start` → 浏览器自动打开（≤ 3 分钟）
2. 新建知识库（≤ 30 秒）
3. 导入 5 篇来源（2 篇 Markdown + 1 篇 PDF + 2 个 URL），等待消化（≤ 12 分钟）
4. 打开 `index.md`，看到自动成形的 wiki（实体页/概念页/来源摘要页）
5. 写一篇笔记，`[[链接]]` 到至少 1 个 wiki 页（补全可用）
6. 提问一个跨来源问题，得到带引用答案，点引用跳转成功
7. 把答案归档为笔记
8. 打开图谱，看到笔记节点与 wiki 节点的连接
9. git log 中可指出第 3 步那次批量 ingest 对应的提交并回滚演示一次

**通过线**：全程无需看文档外的任何解释；任何一步卡死即不通过。

## 5. 信任设计的 UX 表现

| 信任要素 | 界面表现 |
|---|---|
| 溯源 | 所有 Agent 生成页 frontmatter 带 `sources[]`；正文引用可点击跳转 |
| 人审 | 覆盖/合并/矛盾全部进 Review Queue；动作按钮是预定义枚举 |
| 回滚 | Activity/Review 均可跳转 git diff；一次操作 = 一次提交 |
| Note 神圣性 | Agent 建议只出现在侧栏批注；git 历史可证明 notes/ 只被人改 |
| 成本 | ingest/query 逐次显示 token 与费用 |
| 逃生门 | 全库是纯 Markdown，随时用 Obsidian 打开，不锁定 |

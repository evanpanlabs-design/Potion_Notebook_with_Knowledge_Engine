# ADR-002 · v0.2 文档工作台、返修池与 Agent 化路线

> 状态：已接受 · 日期：2026-09-28
> 配套：[ADR-001](ADR-001-mvp-scope.md) · [docs/ARCHITECTURE.md](ARCHITECTURE.md) · [docs/SPEC.md](SPEC.md)
> 背景：MVP 交付后实测迭代（v0.1.x：SSE 引擎工作台、LLM 双角色配置、双协议接入）。v0.2 回应用户八项关切，本文记录数据模型、四条管线与 Agent 化三阶段路线，并沉淀 OpenNotebook 调研的借鉴清单。

## 0. 决策速览

| # | 议题 | 决策 |
|---|---|---|
| D1 | 文档统一工作台 | Note 与 Wiki 双向一等公民：全部文档可查看编辑；投喂合并进笔记流；frontmatter 承载 ingest 元数据 |
| D2 | 变更感知 | 手动「同步」按钮触发，LLM 感知 diff 做局部维护，不搞自动监听 |
| D3 | 返修闭环 | 驳回之外增设返修池（rework pool）：意见进池 → 统一修复 → 回到待审；修复运行期间新意见 deferred |

## 1. D1 · 文档统一工作台与 ingest 元数据

**决策**：不再区分"投喂页"与"笔记页"的主次。`notes/` 是人的原件（可变），`sources/` 是不可变证据层，`wiki/` 是 LLM 综合层。三者在同一个工作台（Notes 视图）里可查看、可编辑：

- **笔记**：`notes/<project>/<name>.md` 物理分层（一层，正则 `^[\w\u4e00-\u9fff-]{1,40}$`）；frontmatter 增 `archived`（归档）
- **库页面**：`wiki/`、`sources/` 走 `PUT /api/v1/pages/*`，保留原 frontmatter 溯源链，补 `prev_sha256`（编辑前整页 hash）+ `updated_at`
- **ingest 元数据**（数据模型核心）：笔记 frontmatter 增加 `ingested_sha256`（上次消化时整页内容 hash）与 `last_ingested_at`。列表接口据此派生三态：

| syncState | 判定 | UI 徽标 |
|---|---|---|
| `never` | 无 `ingested_sha256` | 「未消化」（按钮文案：⚙ 消化此笔记） |
| `synced` | 当前 hash == `ingested_sha256` | 「已同步」 |
| `dirty` | hash 不一致 | 「有改动未同步」+ 列表小圆点 |

**笔记消化管线**：正文快照写入 `sources/note-<name>.md`（原件可变、快照不可变，复用 sha256 幂等判重）→ 复用既有两段式 ingest → 回写笔记 fm。原「投喂页」（Feed）保留为快消化通道，但笔记侧已可完成同样的事——从产品语义上，投喂被合并为笔记的一种用法。

## 2. D2 · 变更感知：手动同步 + LLM 局部维护

**决策**：不做文件监听自动 ingest（成本不可控、打断感强）。改为用户编辑完手动点「⚙ 同步到知识库」，按目标走三条管线（`POST /api/v1/sync`，`maintain-pipeline.ts`）：

| 对象 | kind | 管线 |
|---|---|---|
| 笔记 | `note-ingest` | 快照 → ingestSource → 回写 fm |
| 来源 | `source-reingest` | 幂等重跑 ingestSource |
| wiki 页 | `wiki-maintain` | MAINTAIN_PROMPT：输入=最新版 + git HEAD 上一版 diff + 邻居页（backlinks/outlinks 各前 6 页截 1500 字），输出 updates[]，闸门校验（维护器不能新建页）后落盘 + `maintain:` 提交 |

wiki 局部维护是 v0.2 最重要的增量：它把"知识图谱"从一次性生成物变成可维护的活结构。流式过程经 SSE 在页内引擎工作台显化（与投喂共用 `useEngineStream` hook）。

## 3. D3 · 返修池与批量修复

**决策**：审核动作从二选一扩为三选一：`approve` / `reject`（删除） / `rework`（附意见）。返修数据放页面 frontmatter（`fm.rework = {note, at, status}`），与服务端内存锁 `reworkState.running` 配合实现"运行期间暂停进池"：

- 返修时若批量修复正在运行 → `status='deferred'`（不进池，UI 提示暂缓），否则 `'pending'`
- 「⚙ 统一修复」（`POST /api/v1/review/rework-run`）逐页执行 REWORK_EXECUTOR：只改意见相关内容、其余原样保留、保持 wikilink；完成后删除 `fm.rework`、补 `reworked_at`、回到待审（`reviewed` 不变）
- 修复结束 `bus.emit('review:done')`，deferred 意见在下一轮统一修复时自动回流

为什么用 frontmatter 而不是数据库/JSON 文件：返修意见本质是"这个页面此刻的状态"，随页面走、随 git 留痕、人在编辑器里也能看见和手改——符合"库即记忆"（ADR-001 D1）。

## 4. D4 · 问答局部子图

`GET /api/v1/graph/sub?seeds=a,b`：种子（本次命中的引用页）+ 一跳邻居 + 相关边。前端 `MiniGraph`（无依赖 SVG 径向布局：种子居中、邻居环绕、种子边高亮）在回答结束后由「✦ 关联知识图谱」按钮触发。不放自动展示：避免大子图喧宾夺主，也让"回答 → 证据 → 图谱"的探查路径由用户主导。

## 5. D5 · Agent 化三阶段路线（回应关切 #7）

现状：问答是确定性管道（词法匹配 → 图扩展 → 组装 → 生成），零自主循环（ADR-001 D4 的 MVP 立场）。向"有 ToolCall / SKILL / MCP 能力的通用 Agent"演进，按能力半径分三阶段，每阶段独立可用：

**阶段 A · ToolCall（检索工具化）**：把检索与库操作封装为工具（`search_kb`、`read_page`、`list_graph_neighbors`、`open_subgraph`），query LLM 走 pi-ai 的 tools 通道按需调用；回答从"一次组装"变为"多步检索-综合"。围栏：工具只读 + 步数上限 + 全程留痕（每次调用写 log.md）。这是性价比最高的一步，直接消灭"一次检索不够用"的漏检问题。

**阶段 B · SKILL（流程模板）**：把已固化的管线（ingest / maintain / rework）注册为 Agent 可调用的技能，用户在问答里就能说"把我刚改的那页同步一下"——Agent 调 maintain 技能，复用全部闸门与留痕。技能定义从 `AGENTS.md` 演化而来（程序记忆外化，ADR-001 D1）。

**阶段 C · MCP（外部生态）**：接外部 MCP server（浏览器、文件系统之外的系统）。这是作品集叙事的终点形态：Potion 从"消化你给的文本"升级为"操作你的信息环境"。围栏沿用阶段 A/B：MCP 工具需用户在设置页显式授权，动作类工具默认只读。

不设统一时间表，按春招作品集节奏以阶段 A 为 v0.3 候选首要项。

## 6. OpenNotebook 借鉴清单（回应关切 #8）

调研 [lfnovo/open-notebook](https://github.com/lfnovo/open-notebook) 后按"已借鉴 / 谨慎借鉴 / 仅 roadmap"分档：

**已在 v0.2 吸收**：
- source（不可变证据）/ note（人写综合）分层——对应我们的 sources/ 与 notes/，v0.2 把笔记消化也建成"快照证据"，证据链完整
- 转化模板（transformation = prompt 文件）——对应 MAINTAIN_PROMPT / REWORK_EXECUTOR 的可替换式管线 prompt；roadmap 上可外化为 data/ 下可编辑模板
- wiki 页结构化小节模板——v0.2 GENERATE_PROMPT 已加（实体页：概述/关键事实/关系网络/来源；概念页：定义/机制/相关概念/常见误区）
- 问答后展示证据关联——对应局部子图（D4）

**谨慎借鉴（不直接抄，取思想）**：
- 全文 + 向量双检索、按库限定——我们的 L3.5 可插拔向量槽位（ADR-001 D2）与之同向，等本地 embedding 成本可控再开
- 失败显式报错 + 手动重试——SSE 工作台已把失败过程显化，重试按钮是低成本增量
- chunk 级引用粒度——我们的 locus 定位已够 MVP 用，chunk 化留给向量时代

**仅 roadmap**：TTS / OCR / 多 provider 聚合 / podcast 工作流——与"替你消化知识的笔记本"主线弱相关，不进 v0.x。

## 7. 端点契约变更（v0.2 全量）

| 端点 | 变更 |
|---|---|
| `GET /api/v1/notes` | 返回体增 `project/archived/lastIngestedAt/syncState` |
| `POST /api/v1/notes` | 增 `project` 参数（写 `notes/<project>/`） |
| `POST /api/v1/notes/archive` | 新增：归档/取消归档 |
| `DELETE /api/v1/notes` | 新增：删除笔记（git 历史可找回） |
| `GET /api/v1/files` | 新增：全库文件清单（wiki/sources/meta 分 kind） |
| `PUT /api/v1/pages/*` | 新增：库页面编辑（保留 fm 溯源 + prev_sha256） |
| `POST /api/v1/sync` | 新增：三管线统一同步入口 |
| `GET /api/v1/graph/sub` | 新增：问答局部子图 |
| `POST /api/v1/review` | action 增 `rework`（需 note 意见） |
| `GET /api/v1/review/rework-status`、`POST /api/v1/review/rework-run` | 新增：返修池状态与批量修复 |
| `GET /api/v1/review-queue` | 列表项增 `rework`，另回 `maintenanceRunning` |

log 操作词表扩为 `['ingest','query','lint','review','note','edit','sync','rework']`。

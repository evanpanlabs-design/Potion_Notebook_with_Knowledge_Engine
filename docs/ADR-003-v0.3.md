# ADR-003 · v0.3 Agent 化：自维护图谱、定时任务与收件箱、异步交互面板

> 状态：已接受 · 日期：2026-09-30
> 配套：[ADR-002](ADR-002-v0.2.md)（Agent 化三阶段路线）· [docs/ARCHITECTURE.md](ARCHITECTURE.md) · [ROADMAP.md](../../ROADMAP.md)

## 1. 九项设想评估

| # | 设想 | 优先级 | 依赖 | pi 复用 | 成本 | 归属 |
|---|---|---|---|---|---|---|
| 1 | 图谱自检、自维护 | **高** | maintain 管线（已有）、review queue（已有）、Tavily | 无（纯自研，复用自家管线） | 中 | **v0.3** |
| 2 | 收件箱 + 定时任务 | **高** | agent loop、Tavily 工具、ingest（已有） | —（pi-durable 无 cron，见 §2） | 中高 | **v0.3** |
| 3 | 人工图谱维护建议 | **高**（便宜） | rework 池机制（已有，泛化即可） | 无 | 低 | **v0.3** |
| 4 | skill / MCP 管理 | 中 | agent loop 稳定后才有意义 | **pi-mcp** 客户端直接可用；Agent Skills 规范加载 | 中 | v0.4 |
| 5 | bulletin board | **高**（便宜） | 无硬依赖；与 #2 联动才有灵魂 | 无 | 低中 | **v0.3** |
| 6 | 代码编辑器能力 | 低 | 工具注册表、沙箱集成 | **pi-codemode**（QuickJS/WASM 沙箱，工具注入） | 中高 | v0.5+ |
| 7 | tool/skill 生产与图谱化 | 低 | #4 + #6 | pi-codemode + Agent Skills 规范 | 高 | v0.5+ |
| 8 | workbench | 中 | agent loop 的 event 流（多步任务产生轨迹） | pi-agent-core 事件流 | 中（最小版低） | **v0.3 最小版** |
| 9a | 上下文自动压缩 | **高**（护栏性质） | agent loop | **pi-agent-core compaction**（compact/shouldCompact/prepareCompaction + branch-summarization） | 低 | **v0.3** |
| 9b | 图谱社区化 | 中（尚早） | 图谱规模 | Louvain（原架构已规划） | 中 | 挂条件 |
| 9c | 用户记忆系统 | — | — | — | — | 不做 |

**取舍主线**：v0.3 聚焦「**自主性 + 异步交互**」——让提问球从确定性管道变成会自己排程、自己体检、和人异步对话的助手（ADR-002 阶段 A+B 的落地）；MCP/代码执行/工具生产是能力半径的下一圈（阶段 C），等 loop 在真实使用中稳定后再扩，避免一次吞九项导致全线烂尾。

## 2. pi monorepo 复用调研结论

浅克隆 `earendil-works/pi`（v0.99.1）核实，关键包与结论：

| 包 | 状态 | 对 Potion 的价值 |
|---|---|---|
| `@earendil-works/pi-agent-core` | 已发布 0.99.1（当前用 0.87.1，**需升级**） | **compaction 模块直接复用**（`compact` / `shouldCompact` / `prepareCompaction` / `DEFAULT_COMPACTION_SETTINGS` / branch-summarization）；agent loop 事件流供 workbench 记录 |
| `@earendil-works/pi-mcp` | 已发布 0.99.1 | 独立 MCP 客户端（stdio / Streamable HTTP / 内存测试 transport），零 pi 依赖 → v0.4 接 MCP 时直接 `McpClient`，不必引官方 SDK |
| `@earendil-works/pi-durable` | 已发布但 README 自标注 **Experimental，API 随版本变更** | 提供 phase 检查点 / 中断恢复，但 **scheduler 是任务预留调度器，无 cron/时间触发原语**（types.ts 的 TaskDefinition 无 dueAt/interval 字段）→ 定时任务自建，pi-durable 留观察 |
| `@earendil-works/pi-codemode` | 已发布 0.99.1 | QuickJS(WASM) 沙箱跑模型写的 JS：嵌套工具调用不进 LLM 上下文、只回脚本输出 → v0.5 代码块执行与 tool 生产的试验场 |
| coding-agent 的 skills 体系 | 文档完备 | 遵循 [Agent Skills 规范](https://agentskills.io/specification)：`SKILL.md` frontmatter + 渐进披露（启动只注入 name/description，命中才加载全文）→ 与 CatPaw `skill-creator` 产物**同规范互通**，用户可用 skill-creator 造 skill 直接丢进 Potion `skills/` 目录 |
| chord / pi-server / pi-protocol / pi-client | — | 应用组合运行时与实验性会话协议，对单机 Fastify 架构过重，不引入 |

## 3. v0.3 方案要点

### 3.1 F-1 图谱自检、自维护（设想 #1 + #3 合并实现）

新增 **graph audit 管线**（`audit-pipeline.ts`），可定时（挂 scheduler）或手动触发：

1. **图体检**（纯计算，零 token）：度数异常（孤立节点、超枢纽）、节点名相似度（疑似重复实体）、桥接边冗余初筛
2. **LLM 判定**：对初筛嫌疑批量判定「冗余边 / 缺漏关联 / 重复节点」，产出 proposals
3. **进既有 Review Queue**：复用 approve / reject / rework 三态——不新造审核 UI，AI 的维护建议与人审共用一条队列（与「AI 生成页默认待审」对称：**AI 的维护动作也默认待审**）
4. **缺漏补链的证据顺序**（守住 2026-09-28 溯源决策）：
   - 先查原始素材：`sources/` 全文检索（L1 词法），有依据 → 直接生成关联 proposal
   - 无依据且 Tavily 已开启 → 联网搜索，结果**先物化为 `sources/url-<hash>.md` 证据页**，再允许 wiki 引用；素材和网上都无据 → 明说「无依据，建议人工补充」

**设想 #3（人工建议）**：泛化 v0.2 的 rework 池——任意 wiki 页 frontmatter 增 `suggestions[]`（含 `origin: user|audit`、意见文本），audit / maintain 批次执行前统一读取合并提交。用户在页上留的建议（删某条关联、精简表达、联网补充），下一轮图谱任务一并处理，实现异步交互。

### 3.2 F-2 定时任务 + 收件箱（设想 #2）

**意图入口**：AskOrb 新增 schedule 意图识别——「每天 7 点帮我搜今天最新 AI 资讯」→ LLM 解析为结构化任务定义（cron 表达式 / 主题 / 任务模板 digest）→ 弹确认卡片（展示解析结果，可改）→ 落 `data/tasks.json`。

**运行时**：服务内 60s 粒度扫描 `tasks.json`（nextDue ≤ now 且 lastRun < nextDue → 触发）；每次运行写 run 记录（taskId、startedAt、outcome、产物路径）。

**兜底（错过即补）**：服务启动时扫描 `lastRun < nextDue` 的错过的任务：

- 错过 < 24h → **补做一次**，产物标记「补做」徽标
- 错过 ≥ 24h → **放弃本轮**，在 bulletin board 自动发一张 AI 便利贴告知用户「07:00 的 AI 日报因服务未运行已跳过，可点此手动补跑」

**日报管线**：web_search(Tavily) → 结果物化 `sources/` → LLM 综合生成 `inbox/<date>-<topic>.md`（frontmatter：`kind: bulletin`、`topic`、`generatedAt`、`sources`）→ 收件箱视图（新在前，带未读点）。收件箱内容**天然不进图谱**（inbox/ 不在 scanKb 集合内）；「⚙ 消化进图谱」按钮 = 把该日报作为 source 走既有 ingest 管线——「允许被消化」即复用，零新机制。

### 3.3 F-5 bulletin board（设想 #5）

存储：`bulletins/*.md` + frontmatter——`author: user|ai`、`kind: directive|todo|request|note`、`status: open|done|dropped|replied`、`expiresAt`（保质期，默认 7 天）、`thread`（回复跟帖，嵌套引用 id）。库即记忆 + git 留痕，与 rework 同哲学。

交互：看板视图（按 status 分列）；便利贴可标记已完成 / 放弃 / 回复跟帖；过期自动转 `dropped` 归档不删除。

**AI 侧接入**（这是灵魂）：

- **任务前置读取**：scheduler 触发任何任务前，把 `status=open` 且未过期的 directive 注入任务上下文——「明天日报主题从 AI 资讯改成财经」即由此生效
- **AI 反向发帖**：任务缺数据 / 缺能力时发 `request` 型便利贴向用户提要求（如「Tavily 额度将尽，请更换 key」），同步收件箱角标提醒

### 3.4 F-8 workbench 最小版（设想 #8）

agent loop（pi-agent-core 事件流）序列化为 `data/tasks/<taskId>.md`：frontmatter（taskId / kind / status / startedAt / finishedAt），正文按「背景与目标 → 探索链路（检索/读页/搜索的每步与命中）→ 执行链路（写操作与闸门结果）→ 结果与迭代」四节结构化落盘。Workbench 视图按任务渲染时间线。

图谱化入口预留：这些记录未来可作为「项目经验」被 ingest 消化（呼应设想 #7/#8 远期），本期不做自动消化。

### 3.5 F-9a 上下文压缩（设想 #9 部分）

agent loop 每轮工具调用后 `shouldCompact` 检查（`DEFAULT_COMPACTION_SETTINGS` 起步，预算阈值可配），触发则 `compact`：保留压缩摘要 + 最近 N 轮原文。多步任务（audit、日报）最先受益。前置条件：**pi 三包升级 0.87.1 → 0.99.1**（D1 首项，全量回归 41+ 测试与 e2e 后再动其他）。

### 3.6 Tavily 接入（设想 #1/#2 的公共地基）

- key 已在 `.env`（TAVILY_API_KEY，容器可达 api.tavily.com 已验证）
- **未找到任何 MCP 连接方式配置**（全工作空间检索无果）——且按 2026-09-28 决策 Tavily 本就走 REST 封装不走高开销 MCP，无缺口
- Settings 页新增「联网检索」区块：Tavily Key（留空沿用 .env）、开关（默认关）、月度用量条（1000 次/月免费档，超限提醒）
- `web_search` 作为内部工具注册进工具注册表（TypeBox 自有体系，与既有工具一致）

## 4. 明确不做（本期）与理由

| 项 | 理由 |
|---|---|
| MCP 管理（阶段 C） | ADR-002 已定不设统一时间表；Tavily 走 REST 后本期无 MCP 刚需；MCP 涉及信任 UI、stdio 进程管理、工具命名空间，独立成 v0.4 主线（pi-mcp 已就绪，风险低） |
| skill 管理完整版 | 注册 / 设置页 / skill 编辑器是 v0.4 与 MCP 同期的事；本期 stretch 只做 `skills/` 只读扫描 + 渐进披露注入（约 0.5 天，直接兑现「提问球可扩展」的叙事） |
| 代码编辑器执行（#6） | 与「消化知识」主线弱相关，QuickJS 集成 + 编辑器执行 UI 成本中高，v0.5 |
| tool 生产图谱化（#7） | 依赖 #4 + #6，v0.5+；本 ADR 已在 workbench 与 tools 注册表中预留结构槽 |
| 图谱社区化渐进披露（#9b） | 当前库规模远未到痛点；触发条件：节点 > 300 或 query 组装超预算。埋开关不实现 |
| 用户记忆系统（#9c） | 未想清楚不做；先用 bulletin board 的用户偏好类便利贴观察真实需求 |

## 7. 风险与守门

- **agent loop 围栏**：工具白名单 + 只读优先（写操作一律走 gate executor 不开洞）+ 步数上限 + 每次调用留痕 log.md——阶段 A 围栏原样沿用
- **Tavily 额度**：免费档 1000 次/月；audit 联网默认关、日报单次 ≤ 5 query；Settings 用量条 + bulletin 预警
- **scheduler 单进程内存态**：容器回收丢内存无妨——`tasks.json` 与 run 记录均落盘，启动补偿覆盖；不做分布式
- **pi 0.87→0.99 升级**：D1 一次性完成并全量回归，之后整个迭代锁版本
- **范围蠕变**：九项设想只进五项半，MCP/代码执行/tool 生产明确 v0.4+；本期任何新想法先进 bulletin board 或 backlog，不中途加塞
